# LabelPrint FrontPad Bridge (Chrome / Edge)

Расширение перехватывает сохранение заказа в веб-интерфейсе FrontPad (`order.php`)
и отправляет состав позиций на локальный webhook **LabelPrint Pro**.

## Установка / обновление

1. Запустите LabelPrint Pro. В **Настройках** укажите webhook, например `http://127.0.0.1:8765/`, сохраните, **перезапустите** приложение (слушатель стартует при запуске).
2. Chrome: `chrome://extensions` → режим разработчика → **Загрузить распакованное** (или «Обновить» после правок).
3. Папка `extensions/frontpad-bridge`.
4. Откройте FrontPad **заново** (закрыть вкладку и открыть снова).
5. Иконка расширения должна показать: «Хук на странице FrontPad активен».
6. Кнопка **Тест webhook** — проверка LabelPrint без заказа.
7. Сохраните заказ в FrontPad.

### Если «отправлено: 0»

| Статус в popup | Значение |
|----------------|----------|
| Нет «Хук активен» | Расширение не на этой вкладке / не тот домен / не обновлена вкладка |
| «Вижу order.php» но не «Отправлен» | Смотрите красную ошибку / debug-строку |
| «Пропуск: No positions» | Request body пустой или другой формат — пришлите debug |
| «Ошибка отправки» | LabelPrint не слушает webhook (не запущен / другой URL / URL не сохранён) |
| «Тест webhook OK», заказ нет | Хук не ловит сохранение — Console FrontPad: есть ли `[LabelPrint Bridge] hook active` |

## Как работает

1. Content script внедряет хук в страницу (XHR + `fetch`).
2. При успешном ответе `order.php` (`result: success`) собираются:
   - **Request** → `positions` (состав)
   - **Response** → `order_id`, `order_n`, дата/время
3. Формируется JSON inbox LabelPrint и делается `POST` на webhook.

## Настройки

| Параметр | По умолчанию |
|----------|----------------|
| Webhook URL | `http://127.0.0.1:8765/` |
| Мост включён | да |

Дубли одного `order_id` игнорируются 5 минут.

## Ограничения

- Домен: `*.frontpad.ru` (кастомный хост — добавьте в `manifest.json` → `content_scripts` / `host_permissions`).
- Срабатывает при **сохранении** заказа через `order.php`, не при простом просмотре списка.
- `positions.name` иногда приходит строкой `"A,B"` — парсер режет по запятой, если число частей = числу `productID`.
- Добавки (модификаторы) с `positions.parent` (индекс родителя, в т.ч. `"0"`) склеиваются в **одну позицию**: `name` = блюдо, `addons` / `comment` = список добавок (для шаблона «Кухня чек»).
- `positions.mod=1` означает «у товара разрешены модификаторы», а не «строка — добавка».
- `sku` = внутренний `productID` FrontPad; сопоставление с каталогом — по имени или после настройки артикулов.
- Неофициальный канал; обновление UI/API FrontPad может сломать перехват.

## Отладка

1. Popup расширения: текст ошибки / «Отправлен заказ №…».
2. `F12` на странице FrontPad → Console: нет ли блокировок CSP (редко).
3. Service worker на `chrome://extensions` → «Просмотр service worker» → логи.
4. Папка inbox: `%LocalAppData%\LabelPrintPro\orders-inbox\` — должен появиться `webhook_*.json`.
